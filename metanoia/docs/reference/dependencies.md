## Installing

From the directory that holds `manage.py`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python .install_requirements.py       # installs every requirement, one by one
```

> **The virtualenv must be called `.venv`, never `.env`.** `.env` is the
> committed *settings file* read at start-up (`config/settings.py` →
> `BASE_DIR/'.env'`); a venv with that name replaces it with a directory and every
> run dies with "PostgreSQL 'default' database has no password". `.venv/` is in
> `.gitignore`; `.env` deliberately is not.

`.install_requirements.py` installs line by line (so one failure does not abort
the rest), skips comment and shell-command lines, and reads the `Django` floor
to refuse an interpreter Django 6.0 does not support (3.12–3.14).

Nothing needs a compiler or a Homebrew library: `psycopg2-binary` ships wheels
and the MySQL driver is optional.

## Layout and pinning policy

Each top-level package the project uses directly is followed by the transitive
dependencies it pulls in, so it is obvious why every line exists. Ranges are
`>=known-good,<next-major` (or next minor where a series matters). After changing
a top-level package, regenerate the pins from `pip freeze` and re-test.

## Security and cryptography

| Package | Why |
|---|---|
| `cryptography` (+ `cffi`, `pycparser`) | Token signing, OAuth and TLS helpers (allauth, Apple sign-in JWTs, Web Push VAPID). |
| `django-axes` | Brute-force protection: per-account and per-IP lockout with an auditable `AccessAttempt`/`AccessLog` trail; complements allauth's throttling, which blocks but records nothing. |
| `nh3>=0.3,<0.4` | Allowlist HTML sanitiser (Rust ammonia binding, prebuilt wheels). Cleans educator-authored rich text (lesson blocks, support answers, HTML notifications) on save **and** on render — `core/sanitize.py`. |
| `qrcode` | Renders the TOTP enrolment QR code for `allauth.mfa`. |
| `fido2>=1.1.2,<3.0` | Imported unconditionally by `allauth.mfa` (WebAuthn support). |

Multi-factor authentication is allauth's own `allauth.mfa`, not django-otp: it
hooks into the login, signup, social-login and password-reset flows already in
use instead of adding a second login pipeline. `qrcode` and `fido2` are its two
extras.

## Error reporting

`sentry-sdk>=2.20` — optional, dormant until `SENTRY_DSN` is set. Aggregates
unhandled exceptions across servers. Configured with `send_default_pii=False`,
so no request bodies, cookies or user identities leave the platform by default.

## Databases

`psycopg2-binary` — the PostgreSQL driver for the primary (`default`) database.

**MySQL is optional and off.** There is no `backup` database alias, so no MySQL
driver is needed for a normal install. `mysqlclient` used to be a required line;
it is the one package that cannot install without system libraries (pkg-config
and mysql-client headers), so it broke the install for everyone who never used
the backup database. To enable the disaster-recovery copy, add the `backup`
alias described in [configuration.md](configuration.md#5-database), set
`MYSQL_*`, then install **one** of:

* `PyMySQL>=1.1,<2.0` — pure Python, no build step; `settings.py` already falls
  back to it through `pymysql.install_as_MySQLdb()`.
* `mysqlclient>=2.2.7,<3.0` — faster C extension; needs headers first:

```bash
brew install pkg-config mysql-client
export MYSQLCLIENT_CFLAGS="-I/opt/homebrew/opt/mysql-client/include/mysql"
export MYSQLCLIENT_LDFLAGS="-L/opt/homebrew/opt/mysql-client/lib"
```

## Integrations: Anthropic, Microsoft Graph, YouTube

| Package | Why |
|---|---|
| `anthropic>=0.69.0` | Official SDK behind the server-side Claude helpers (recaps, session follow-ups, AI authoring). Installed by default; dormant until `ANTHROPIC_API_KEY` and `ADMIN_AI_ENABLED=true` are set — without them those features report "not configured". |
| `msal>=1.28.0` | Microsoft auth library: the app-only (client-credentials) Graph token for the Teams live classroom (`apps.msteams`). Dormant until `MS_GRAPH_*` is set; see `docs/TEAMS_INTEGRATION.md`. |
| `google-api-python-client>=2.150.0` | YouTube Data API v3 client (upload, read, scan). |
| `google-auth>=2.35.0` | Credentials and token refresh. |
| `google-auth-oauthlib>=1.2.1` | One-time consent → refresh token. |

YouTube is only the nightly **backup** copy of class recordings
(`apps.livesessions.youtube_backup`); students watch from OneDrive. The timer
runs `run_scheduled_jobs --tick youtube` at 00:00 SAST: up to six recordings a
night (an upload costs 1,600 of ~10,000 quota units/day), each filed into its
institution + programme playlist. Without these packages or credentials it stays
off. Credentials: `YOUTUBE_CLIENT_ID` / `_CLIENT_SECRET` / `_REFRESH_TOKEN` (one
consent with the single scope `youtube.force-ssl`, minted by
`deploy/mint_youtube_token.py`) and `YOUTUBE_CHANNEL_ID`.

## Production web server

Gunicorn with uvicorn workers behind Caddy on the server
(`deploy/server/metanoia.service`, `deploy/server/Caddyfile`).

| Package | Why | Pin notes |
|---|---|---|
| `gunicorn>=26.2,<27.0` | Process manager and HTTP front end: supervises, restarts and load-balances the workers, binds the platform's `$PORT`. | |
| `whitenoise[brotli]>=6.12,<7.0` | Serves `/static/` (compressed, cache-busted) from the app process; Caddy only proxies. | |
| `uvicorn[standard]>=0.52,<0.53` | ASGI worker (uvloop, httptools, websockets). | Minor-pinned (0.x). |
| `uvicorn-worker>=0.4,<0.5` | The gunicorn worker class `uvicorn_worker.UvicornWorker`. | The in-tree `uvicorn.workers.UvicornWorker` is deprecated; this is its maintained home. |

* `runserver` is a development server and must never face the internet.
* Gunicorn does not speak ASGI on its own, and this project **is** ASGI —
  Channels carries live chat and notification push over WebSockets
  (`config/asgi.py`). Always run it against `config.asgi` with the uvicorn
  worker, never `config.wsgi`: the WSGI path serves ordinary HTTP and then drops
  every WebSocket handshake, which shows up as chat stuck on "connecting…"
  rather than as an error anyone can find.

```bash
gunicorn config.asgi:application \
    -k uvicorn_worker.UvicornWorker -b 0.0.0.0:$PORT --workers 3
```

## Optional and retired packages

* **WeasyPrint** (optional, not listed): renders the achievement certificate PDF
  in `apps/reports/services.py::_render_pdf`. The import is guarded, so without
  it the `Certificate` row is still created, just with no PDF. Not installed by
  default because it needs system libraries (pango, cairo, gdk-pixbuf;
  `brew install pango` on macOS) and would break the whole install. Invoices and
  receipts do not need it. To use it: `pip install "weasyprint>=63.0,<70.0"`.
* **Celery**: removed — it only ran the retired CrewAI media pipeline. No task
  queue is needed; `django-redis`/`redis` remain for the optional cache.
* **CrewAI, Ollama, faster-whisper**: the page assistant was removed to free
  server resources. Live classes are Microsoft Teams, recaps come from the Teams
  transcript, and the Claude admin layer (`anthropic`) stays for admins.
* `qrcode` and `openpyxl` were once listed twice; they are required above (for
  MFA and the `.xlsx` exports).

## External accounts and services

`pip install -r requirements.txt` installs only Python libraries. These services
are configured through `.env` (copy `.env.example` first). Required ones are
marked; the rest have safe development defaults.

1. **PostgreSQL — required** (the `default` database). Install or use a managed
   instance; `createdb metanoia_db`; `createuser -P metanoia`
   and grant it on the database; set `POSTGRES_DB`, `POSTGRES_USER`,
   `POSTGRES_PASSWORD`, `POSTGRES_HOST` (127.0.0.1), `POSTGRES_PORT` (5432); run
   `python manage.py migrate`.
2. **MySQL — optional, off by default** (disaster-recovery copy). Create a
   utf8mb4 database and user, add the `backup` alias, set `MYSQL_DB`,
   `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_HOST`, `MYSQL_PORT`, install a driver
   (above), and keep it in sync with `migrate --database=backup`. Nothing reads
   from it implicitly. `.academic_seed.py --fresh` wipes and migrates every alias
   in `DATABASES`, so a fresh seed touches MySQL too.
3. **Redis — optional in development, used in production** (cache and the
   Channels layer behind live chat, the bell and lesson presence). Run
   `redis-server` or a managed instance; set `USE_REDIS=true` and `REDIS_URL`.
   Off, Django uses an in-memory cache and everything still works.
4. **SMTP — required for real e-mail** (verification, password reset,
   notifications, announcements); the default backend prints to the console. Get
   credentials (for example a Gmail app password, SendGrid, Mailgun, SES,
   Postmark) and set `EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend`,
   `EMAIL_HOST`, `EMAIL_PORT` (587 with `EMAIL_USE_TLS=true`, or 465 with
   `EMAIL_USE_SSL=true`), `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`,
   `DEFAULT_FROM_EMAIL`, and `ACCOUNT_EMAIL_VERIFICATION=mandatory`. Branded
   e-mails are in `templates/communication/email/` and `templates/account/email/`;
   wording and brand come from `.strings.json`.
5. **Google and Apple sign-in — optional.** Google: a "Web" OAuth client with
   redirect URI `https://learn.metanoiagroup.co.za/accounts/google/login/callback/`
   → `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_SECRET`. Apple: `APPLE_SERVICES_ID`,
   `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY_PATH` (the `.p8` key, outside
   the repository); until set the Apple button shows "soon". Do **not** also add a
   "Social application" row in the admin — a settings app plus a database row for
   the same provider breaks sign-in.
6. **Video calls — Microsoft Teams only** (`MS_GRAPH_*`,
   `docs/TEAMS_INTEGRATION.md`). Without Teams the platform says a call cannot be
   started.
7. **Anthropic — optional.** Set `ADMIN_AI_ENABLED=true`, `ANTHROPIC_API_KEY`
   (console.anthropic.com) and optionally `ADMIN_AI_MODEL`. No key → recaps and
   follow-ups are skipped and AI authoring refuses politely; nothing else is
   affected. The `AI_ASSISTANT_ENABLED` / `AI_LLM_*` settings of the retired
   CrewAI widget still exist but drive nothing.
8. **Django superuser — required** (to reach `/admin/`). `.academic_seed.py`
   creates the team accounts, all verified and onboarded: the named staff
   mailboxes and dev@ (superusers) and accounts@, info@, learninghub@ (staff, the sending
   mailboxes). Their first password is `--password` / `SEED_ACCOUNT_PASSWORD`, or
   a random one printed once.
9. **Other integrations — optional, dormant until configured**:

| Integration | Variables |
|---|---|
| Metanoia Mail and outbound mail | `EMAIL_{ACCOUNTS,INFO,LEARNINGHUB}_{USER,PASSWORD}` (own-domain IMAP/SMTP, `mail.metanoiagroup.co.za`) |
| Microsoft Teams / OneDrive | `MS_GRAPH_*` (live classes, recordings, transcripts) |
| YouTube backup | `YOUTUBE_*` |
| WhatsApp Cloud API | `WHATSAPP_*` (`docs/whatsapp/SETUP.md`) |
| Desktop push | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` |
| PayFast | `PAYFAST_*` plus `PAYMENTS_ENABLED=true` to take money |
| Sentry | `SENTRY_DSN` |

Before any non-local deployment also set `SECRET_KEY` (long and random),
`ALLOWED_HOSTS` and `DEBUG=False`.

## Full setup, in order

```bash
cd metanoia
python3.12 -m venv .venv && source .venv/bin/activate   # NOT .env
python .install_requirements.py            # 1. dependencies
python .academic_seed.py --password '…'    # 2. database, academic structure, team, mail, shop
                                           #    (--fresh first DROPS every table)
python run_server.py                       # 3. serve on the LAN
```

Step 2 runs `migrate` itself and is safe to re-run on a live database. Run
`python manage.py collectstatic` if you serve static files in production.
