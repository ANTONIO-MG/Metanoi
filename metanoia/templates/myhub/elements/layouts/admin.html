{% comment %}Shared layout for every MyHub / app page: the navbar, the sidebar, the content column, the footer and the global scripts. Blocks: ``head_title``, ``additional_css``, ``message``, ``content`` and ``additional_js``. Includes ``partials/head-css.html``, ``partials/_loader.html``, ``partials/_alerts.html``, ``partials/navbar.html`` (with ``has_sidenav=True``), ``partials/sidenav.html``, ``myhub/elements/footer.html`` and ``partials/_media.html`` (the global lightbox, media grid and dropzone). Theme: ``data-bs-theme`` is stamped server-side from the user's saved preference (``core.context_processors.ui_chrome``) so a dark-mode user's first paint is already dark. On "auto" the attribute is omitted and ``prefers-color-scheme`` decides. Assets: ``global.min.js`` supplies jQuery + Bootstrap 5, so the Social ``vendors.js`` bundle is deliberately NOT loaded (it would double-load Bootstrap). Pages needing a plugin name it in their own ``additional_css`` / ``additional_js`` block. ``metanoia-ui.css`` (the Metanoia site look) must stay the last site stylesheet before ``dark-twins.css``, the dark-theme twins for page stylesheets (generated by ``manage.py build_dark_twins``). The trailing scripts add upload progress to file forms (``upload-progress.js``), person cards on names (``person-card.js``), ``textarea[data-autosize]`` growth to ~10 lines (``autosize.js``) and preview cards under shared links (``link-preview.js``). Inline styles: compact dashboard chrome — near-zero side margins, a fixed-width left sidebar and a wider centre column that fills the rest of the screen. The sidebar keeps its usual width and the centre takes ALL the rest. The centre deliberately has no max-width: it used to carry ``max-width: calc(100% - var(--app-sidebar-w))``, which double-counted the rail — the sidebar already consumes its width as a flex item, so subtracting it a second time left a sidebar-wide strip of dead space down the right of every page whenever the rail was open. ``flex-grow`` against the free space is the whole calculation; ``min-width: 0`` keeps a wide child (a table, a calendar grid) from pushing the column past the viewport instead of scrolling inside it. Also here: colourful sidebar icons, the HTMX boosted-navigation progress bar and collapsible sidebar submenus. Collapse, hover-reveal and scroll-memory live in ``css/chrome.css``. HTMX: boosted navigation swaps ONLY ``#appContentCol``, so the shell's WebSocket connections survive navigation. Content-internal links/forms are NOT boosted (``hx-boost="false"`` on ``#appContentCol``), so exams and uploads stay full-page. See ``docs/HTMX.md``. For the same reason a page's ``additional_css`` block is rendered at the top of ``#appContentCol`` (not in ````) so a boosted swap carries it; otherwise a boosted-in page would lose its own styles. Body: ``app-shell`` marks the layout that renders a footer — ``css/chrome.css`` uses it to pin that footer to the bottom of the viewport on a short page. A pre-paint script restores the collapsed sidebar state before first render. A super student always sees a banner of whose eyes they are looking through. The phone menu button lives in the navbar (``partials/navbar.html``, ``has_sidenav``). The site-wide announcement banner is toggled from ``.strings.json`` → ``dynamic.announcement``.
