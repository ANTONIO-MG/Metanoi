{% extends 'layouts/auth.html' %} {% comment %}Registration wizard, step 2 — "How would you like to register?". Two paths, chosen with plain links (``?path=programme`` / ``?path=oneonone``) so they work without JavaScript; the script switches between them in place: - Programme & modules (group classes, billed per module per month); - One-on-one coaching (billed per module per hour at `one_on_one_rate`). Each module gets an hours box ("later" = 0, buy later) and nothing is compulsory. One picker serves both paths; the hidden ``track`` input says which. Below it, on the one-on-one path only, "Institution or programme not listed?" posts a request staff complete by hand (accounts.OneOnOneRequest, `one_on_one_form`). Context: `reg_path`, `reg` (saved `programme_id`, `cohort_id`, `module_ids`), `institutions` and `institutions_data` (JSON for the picker), `reg_hours` (saved hours per module), `other` (typed "Other institution" values and `errors`), `posted_institution`, `one_on_one_rate`, `one_on_one_form`. Overrides `title`, `card_col`, `oblique`, `auth_card`, `extra_css` and `extra_js`. Picker behaviour (inline script): - The chosen institution is shown in its own words (name, description, logo), so a student can confirm they picked the right one before choosing a programme. - "Other institution": the institution + cohort/year boxes open and are required (the server checks again); the cohort picker steps aside, as the cohort is typed instead. The one-on-one request form's institution select does the same for its two boxes. - Programmes with ``mandatory`` (IAC and the like): every module is compulsory, so all are ticked and stay ticked (group path only). - A bundle discount applies once every module it names is ticked — the same rule the review page and the invoice use (apps.shop.pricing). Bundles are for monthly group classes only. - On the one-on-one path a module row holds an hours select, so the row is a div and only the module name is the label (a select inside a label would toggle the tick on every click). The green state is restored on Back. - A prior selection is restored on Back from step 3, or when the page is sent back with errors. Styling notes: programme options are plain bordered cards rather than ``.btn-outline-secondary`` — the Bootstrap button's own border/background rules (and its hover/focus/active states) kept overriding the "selected" utilities, so the choice never looked chosen; owning the whole style means the green state cannot be argued with. The selected programme's tick is drawn in CSS, so it never depends on an icon font. The old theme sets ``.form-check-input:checked{background-color:transparent; border-color:transparent}`` and pushes the tick off with ``background-position:100%``, so a checked box renders as a bare filled square with no mark; the boxes therefore reuse ``.tick-green`` (from auth_base.html), and ``.tick-round`` is its radio-shaped variant for the cohort picker. {% endcomment %} {% load static %} {% block title %}Choose · {{ brand.name|default:"Metanoia Group" }}{% endblock %} {% block card_col %}col-xl-9 col-lg-11{% endblock %} {% block oblique %}{% endblock %} {% block auth_card %}
