{% extends base_template|default:'profiles/shell.html' %} {% load static %} {% comment %} MODULE FEED. Landing tab is the schedule (block → week → material); every other tab is the same material filtered by kind, through `_module_item.html`. Context comes from apps.learning.module_feed. Tabs, in order: schedule (landing), messages, notifications, live sessions and the filtered material tabs. - Schedule: a trial countdown shows only for a student actually on a live trial (``gate.enrolment`` is ``None`` for staff/authors, so it is guarded before the property is read). The per-cohort picker (content "Option B") lets authors preview/build any intake's schedule. Each block has a header (the outer tear-drop) and a body: its own material, then the weeks. Topic sub-sections inside a week are a series of topics, each with its materials. A week the student has not paid for shows its title and dates and a call to action, no material. - Messages: the module's group chat — the same messenger component as the Messages page, so ``additional_css`` includes ``communication/_chat_styles.html``. Inside a tab the thread has the page header and the tab strip above it, so it gets a little less height than on the full Messages page — and no conversation list beside it, so it spans the full width. The chat script lives INSIDE ``profile_content`` (not ``additional_js``) so it swaps in with the tab under HTMX and tears its socket down when you switch tab. - Live sessions: a one-on-one student sees their own sessions, their hours and where to book. - Filtered material tabs also list imported YouTube session recordings mapped to this module + intake. Scripts (in the content block, so they also run after an HTMX tab swap): - ``#mat-`` (a rail link or a refused open) opens its block and week, scrolls and flashes it. A row in a week that has not loaded yet is tried again on each ``mf:weeks-loaded`` event. - The progressive loader: the first paint carries the previous, current and next week; every other week is a ``[data-mf-lazy]`` placeholder whose body is fetched from ``learning:module-weeks`` a few at a time once the page is idle — or at once when the student opens that week. The server gates each week the same way as the first paint, so nothing locked ever reaches the page. A week asked for but not returned shows "Nothing to show"; a failed fetch marks the placeholder ``data-mf-failed`` and opening the week (``show.bs.collapse``) fetches it again, as it does for a week opened before its turn. The loader stops once the tab has been swapped away under HTMX.{% endcomment %} {% block additional_css %} {{ block.super }} {% include 'communication/_chat_styles.html' %} {% endblock additional_css %} {% block additional_js %} {{ block.super }} {% endblock additional_js %} {% block profile_content %}
