{% comment %}The top navbar on every page: brand, page links, search, alerts and the account menu for signed-in users; Login / Sign up for everyone else. Include parameter: ``has_sidenav`` (true from ``myhub/elements/layouts/admin.html``) — when the sidebar drawer is on the page, the left ☰ is the phone menu. - Phones: one menu button opens the sidebar drawer (all the navigation); it used to sit in a separate "Menu" bar under the navbar, beside a second ☰ that only opened search and the icons. With the drawer present, the right-hand toggler only reveals search, alerts and the account menu, so it gets its own icon. - The page links sit in the website's pill nav: the white highlight marks the current page and glides to whatever is hovered (``js/metanoia-ui.js``). - Dashboard lives here rather than in the sidebar: it is the page people go back to most, and the navbar is on every screen — including the ones (a profile, a module feed) where the sidebar is collapsed or scrolled away. - Super student (``core.student_view``): off, it opens the picker; on, it shows what you are viewing as, and the way back out — always one click. - A parent's "My Programme" shows their child's progress — the child chosen on their home page (``core.scoping.viewing_child``). - Desktop alerts (Web Push): ``chrome.js`` shows that item when the browser can do it. - Account menu: ``data-bs-display="static"`` is deliberately NOT set — it disables Popper, which is what let this menu run off the right-hand edge. With Popper on, ``dropdown-menu-end`` anchors it to the avatar's right edge and it flips/shifts itself back into the viewport. ``.su-popout`` caps its width and height so it can never overflow either axis. "View profile" is a padded ``
  • `` button, not a ``.dropdown-item``: that is ``width:100%``, and with ``mx-3`` on top it measured wider than the menu it sat in. The (currently empty) ``if not is_parent`` slot was for the content index, which spans the whole platform. - The theme switch is the same setting as Preferences → Theme on the settings page: ``js/theme.js`` applies it here and POSTs it to ``accounts:set-theme``, so flipping it in the navbar is remembered on the next sign-in. - Logged-out actions: the landing page used to add a WhatsApp button and a "Get the Blueprint" button here, which put three outbound CTAs in the navbar competing with the one thing this bar is for — getting into the Hub. Both destinations are still on the page (the Blueprint under ``#blueprint``, WhatsApp in the footer's contact line), where the reader has the context to want them. Login / Sign up are internal links — never ``target="_blank"``. Each auth page hides its own button: the login page shows only Sign up, the sign-up page shows only Login; everywhere else logged-out (landing, password reset) shows both. Sign up uses the same ``.su-pill`` as Login beside it: the pair reads as one control, so they match in height, type and colour rather than one being a solid accent and the other an outline.{% endcomment %}{% load people %}{% load static %}
