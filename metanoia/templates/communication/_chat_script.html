{% load people %}{% comment %}The messenger's behaviour, shared by the Messages page and embedded threads. Message text arrives already escaped and linkified by the server (``body_html``, apps.communication.links). On a page that embeds only a thread, the list and new-group hooks find nothing to bind to. Context: ``active_group`` (may be unset → the script idles). What the script does: - Message runs: consecutive messages from the same person inside a short window are drawn as one run — one name/time line, one avatar, tighter bubbles. A run starts on a new day, a new sender, or after a gap. Avatars are the sender's photo, initials only when they have none; day dividers read Today / Yesterday / weekday / Last week / month; read ticks show one tick when sent and two blue ticks once someone has read it. Shared media render as a thumbnail grid that opens the lightbox. Text is the server-escaped HTML (links made clickable), with plain escaping as a fallback. - The thread re-renders only when something actually changed — read ticks and edits mean a plain length check would miss updates. A new message from someone else plays a sound, and the active conversation is kept marked read (server + local seen store). - Conversation list: unread rings, green "new" badges and a sound; an incoming meeting rings when it goes live (the toast is _chat_call_ui.html). - Typing indicator: best-effort, cross-tab for now; ``window.chatShowTyping`` lets a future websocket/presence signal drive it. - Reply / edit / jump-to-quote. Sending with no text and no files does nothing; a refused send says why (not a member, muted, not connected yet…) in the API's own words. - Group video call (Microsoft Teams; groups only): the button is a plain POST form, so it works without this script; the script only gives feedback and stops a double click minting a second request. - New group, and client-side conversation search. Refreshing: the WebSocket (``/ws/chat//``) is the primary channel and pokes an instant refresh on every new message. Polling stays only as a fallback and is deliberately quiet: a guarded interval skips its tick whenever the tab is hidden (no work in a background tab) and runs only every n-th tick while the socket is live (so a safety reconcile still happens, just rarely). Messages poll every 5 s without a socket (~30 s with one), the conversation list every 6 s (~30 s) and meetings every 20 s (~60 s). When the socket drops, polling speeds back up so nothing is missed. Teardown: when HTMX swaps the page away (``Metanoia.onTeardown``), the chat closes the socket (and stops it reconnecting), clears every interval and drops its document-level listener, so nothing leaks. No-op without HTMX.{% endcomment %}
